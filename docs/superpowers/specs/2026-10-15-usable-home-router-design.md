### 已确认路线（2026-10-28）

1. routerd 是与 NetworkManager 同类的独立网络管理器，与 NetworkManager、systemd-networkd、dhcpcd、ConnMan 等通用网络管理器互斥。NixOS 安装软件、启动服务和提供首次引导配置；日常网络由 routerd 管理，不依赖 networkd 或 nixos-rebuild。
2. 互斥采用配置期检查和运行前检查；发现冲突明确拒绝，不自动停止其他管理器。仅生成/Web 预览模式不接管网络。
3. 不新增 LAN 改址确认、倒计时、断联看门狗或超时自动回滚。页面提示断联影响和新管理地址，提供控制台恢复说明。应用步骤报错的失败恢复按第 4 节保留。
4. 其余建议接受：配置版本、应用失败恢复、真实状态、信任区域和受限特权执行。Docker 用于 Web/API 预览；路由行为在隔离 VM 和后续硬件验证。

## 3. 配置与接口契约

保留 Go、内嵌原生 Web、JSON 配置和 SQLite 的现有架构；避免为该目标迁移到新前端框架。

- `config.json` 表示已保存意图；应用中的候选、最近成功应用版本分别保存。
- 配置新增版本号和修订号；旧版本有显式迁移和备份，不接受静默丢弃未知字段。
- 并发修改使用 revision/If-Match。过期版本返回 409，UI 提示重新加载，不覆盖别人已保存的修改。
- Web 表单、JSON、校验、生成器使用同一字段契约；带宽单位统一并在页面标明。
- 核心配置只保留一个权威入口。QoS/DDNS/IPv6 等不能在顶层和 plugins 中维护两份互相独立的 enable/config。
- 现有副本有冲突时给出迁移诊断，由用户选择；不能默默选择覆盖。
- 所有错误有 code、message、fieldErrors；页面定位到字段，保留输入。
- 默认 API 隐藏密钥；未修改保持原值，显式清空是独立且可识别的操作。备份可含秘密但必须明确标识。
- 保留 `/api/v1/config`、`/apply`、`/jobs` 等现有端点；结构变动提供兼容期并同步 UI。

## 4. 应用事务与恢复

`POST /apply` 捕获一个不可变的配置修订，返回 202 和 jobId，由单个有界 worker 串行执行。
队列满或已有应用任务时返回明确的 busy/conflict，不无限阻塞 HTTP handler。

阶段：校验 → 创建候选目录 → 原生命令预检查 → 保存恢复点 → 激活 → 运行验证 → 完成。
每个阶段记录开始/结束、错误、脱敏诊断；每条外部命令有 timeout，不拼接用户输入到 shell。

作业结果至少包含 mode、stage、status、configRevision、appliedRuntime、warnings、error、rollbackStatus。
生成模式成功只表示生成成功；缺少必要服务、必要模块失败、跳过必需步骤不能报告运行应用成功。

网络变更与应用失败恢复边界：

- 激活前保存运行资源恢复点和任务阶段；应用步骤失败时恢复上一成功版本，逐步记录结果。
- 恢复覆盖已修改网络资源、服务配置和专属规则，不能只复制 generated 目录；恢复失败必须单独报告。
- 恢复不能覆盖用户在应用期间另行保存的新意图；保存、候选和成功应用版本分开。
- LAN 改址展示新管理地址和重连指引；浏览器断联不视为应用失败，不增加确认事务、超时或断联自动回退。
- 进程中断任务标记 interrupted，开机从最近成功应用版本恢复运行状态；这是启动恢复，不是改址超时回滚。
- 首次安装无成功版本时给出控制台恢复步骤，不能伪报恢复成功。
- 应用成功与互联网健康分开；外部探测失败作为诊断，不撤销有效运行配置。

## 5. NixOS 运行集成

新增显式的 managed-router 部署配置，保留原 generate-only 模式，升级不自动接管网络。
NixOS 模块安装依赖、创建服务/目录、提供首次引导网口映射；日常 Web 更改不依赖 nixos-rebuild。

- 网络：routerd 通过受限执行器和 netlink/结构化 iproute2 参数管理专属 bridge、WAN、LAN、VLAN，仅操作显式受管接口。DHCP/PPPoE 使用专属协议子进程，不依赖另一通用网络管理器。
- WAN：DHCP、静态、PPPoE；PPPoE 由专属 pppd 服务管理，凭据写入受限文件，NAT 跟随实际出口。
- DHCP/DNS：专属 dnsmasq 配置、租约路径与服务；应用前语法检查，配置修改使用能够真实载入变更的动作。
- 防火墙：只管理 routerd 专属表；完整 input/forward/NAT，默认拒绝 WAN 管理与非请求入站；允许必要 DHCP/IPv6 协议。
- 禁用 NAT/规则/插件时撤销旧运行资源；重复 apply 不累积规则。
- 管理入口：LAN-only，覆盖 IPv4/IPv6；管理端口不依赖全局 allowedTCPPorts。不可将“允许监听所有地址”误认为 LAN-only。
- WiFi：iw/nl80211 能力发现、hostapd 专属实例，接口/信道/频段组合经校验；密钥不写进 Nix store 或日志。
- 访客：显式隔离域，需阻断二层及三层到家庭 LAN/管理面；不能只用 AP isolate 或同桥上的 IP input 规则冒充隔离。
- SSH：管理明确的 sshd 配置实例/片段，校验、加载和状态回读；服务端口、密码/root 策略与页面一致。
- 开机从最近成功应用的配置恢复；更新程序保留 config、DB、备份及成功应用版本。
- API 低权限运行，拆分本地受限特权执行器，验证对端身份并限定接口、路径和命令集合。不开放任意命令/脚本 API。现有 root API 是待迁移实现，不作为验收完成标准。

### 管理接口与 overlay 的信任边界

独立审阅指出 LAN-only 管理与 overlay 远程接入之间需要明确区分。按用户接受的其余建议，默认值如下：

- 家庭 LAN、访客、WAN、overlay 分别分类；不会因为 tailscaled/zerotier 服务启动就把 overlay 视为家庭 LAN。
- 默认只允许受信家庭 LAN 访问 Web/API 和 SSH。WAN、访客及 overlay 到路由器管理端口均拒绝，IPv4/IPv6 一致。
- overlay 路由通告只允许显式配置的家庭网段；通告路由不等于允许访问路由器自身，也不自动开放其他 overlay、访客网段或 WAN 中继。
- 如用户要求通过 overlay 管理路由器，作为单独的显式管理授权配置，列出允许的接口/来源网段，并加入访问正反例验收。不是启用插件的隐式副作用。
- VM/本地控制面测试需要证明：允许的 overlay 到 LAN 数据流可通，默认 overlay 到 Web/API/SSH 不通；禁用插件后相关路由和规则撤销。

## 6. Web 与真实状态

- 所有可编辑页：未保存、已保存未应用、应用中、成功、失败/已回退均可区分。
- 插件保存统一返回结构化结果，部分失败不宣称全部成功；离页保护与撤销一致。
- 顶部 Apply 跟踪作业最终结果；刷新、离页、重连后可恢复跟踪；展示必要错误而非原始 JSON。
- 页面有生命周期；轮询只在可见页面运行，离页取消，避免重复计时器和旧请求覆盖新页面。
- 状态字段包含 source、observedAt、available/reason；没有硬件和采集失败不能返回伪造能力或 0 在线设备。
- 区分链路连接、获取 IP、默认路由、DNS 可用和互联网探测，不以网线插入证明联网。
- 宿主 uptime 和后端进程 uptime 分开展示。
- 客户端区分 DHCP 租约、静态绑定、邻居可达和 WiFi 关联；租约到期不是 lastSeen。
- 无无线硬件时 WiFi 页显示明确原因并禁用相关编辑；后端也拒绝不支持的组合。
- 插件目录始终可管理；被禁用插件的业务入口隐藏，直接路由/API 返回 disabled。设置页和运行操作的边界明确。
- 保留已经移除总览 JSON 的用户修改；调试信息另设明确入口，不把调试卡片作为产品完成度。

## 7. 高级与可选模块的验收责任

| 功能 | 运行实现方向 | 必需证明 |
|---|---|---|
| QoS | tc，按配置选定的整形策略与每设备规则 | 实际吞吐限制、禁用清理、错误上报 |
| 家长控制 | 定时规则引擎 + nft 转发控制 | 周历/跨午夜/时区、立即断网与放行 |
| DDNS | provider 适配器与定时更新 | 准确请求、记录更新、失败重试；真实账号集成单独验收 |

| UPnP | miniupnpd，仅 LAN 请求 | 映射创建/查看/撤销、禁用无残留 |
| AdBlock | 下载校验缓存 + dnsmasq | 域名实际拦截、下载失败沿用可用缓存 |
| Traffic | 接口/设备采集与保留策略 | 产生流量后计数变化、历史可查询、停用行为 |
| Mihomo | 专属配置与服务 | DNS/代理真实流量、关闭恢复直连、无秘密泄漏 |
| VLAN | routerd VLAN/桥 + 独立 DHCP 与 nft | 各段获址、隔离、删除清理 |
| Tailscale | 官方/外部 Headscale/本机 Headscale | 登录、路由通告、控制面可达、停用撤销 |
| ZeroTier | 官方/自建控制面 | 入网、路由生效、停用撤销 |

三节点 VM 的路由配置必须由 routerd 的引导与 API 生成/应用，不能在 fixture 中写好所验收的路由规则。

每项记录命令、版本、日志和实际结果。不能用 Go 测试代替部署，用生成文件代替流量，用单节点代替多节点。
完整完成判定要求矩阵全部满足；外部设备/凭据未提供时保持对应验收未完成，不缩小目标。
