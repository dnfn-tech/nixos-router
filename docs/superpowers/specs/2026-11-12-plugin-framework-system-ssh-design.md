## SSH 归属

1. 移除 Web SSH 页面、菜单、编辑控件和配置型伪运行状态。旧页面链接显示迁移说明，不保留可编辑表单。
2. 路由器不生成 sshd 配置，不修改公钥，不启停或重载 sshd，不改变系统 SSH 启用状态、认证策略或监听地址。
3. 旧持久化配置、备份及 last-good 中的 ssh 字段必须能兼容读取。采用版本迁移，备份原始字节后丢弃废弃字段；迁移不得改变系统 SSH。新版本规范配置与 schema 不再包含 ssh；旧客户端提交废弃字段得到明确迁移错误，不静默接受为有效设置。
4. 加载 last-good 使用既有只读兼容机制，不在恢复路径改写历史文件；需要支持含旧字段的 executor 恢复输入。
5. 保留 NixOS 声明的 SSH 监听端口到管理面防火墙的单向输入，完全不依赖旧草稿 ssh.port。管理访问控制仍由路由器防火墙执行，SSH 服务本身由系统管理。
6. 系统未启用 SSH 时不默认假定 22；启用且存在多个监听端口时全部纳入保护。保持现有 WAN/无线访问边界，不能通过端口转发绕开。

## 模块注册与配置

引入独立模块注册包，为内置模块提供唯一 ID、版本、标题、可选导航、配置描述、能力要求、支持的运行模式及固定生命周期接口。注册表不可由 HTTP 配置任意扩展；重复 ID、无效 ID 和冲突声明在启动或构建测试中失败。

配置解析/校验与生成保持纯函数，供 API 和 executor 共用；模块不能绕过鉴权、revision、secret references 或 executor 边界。需要的生命周期是 validate、prepare/render、activate、disable、status；实际副作用通过核心允许的操作完成，不给模块公开任意 root 命令接口。

API 列表和导航由注册表派生，区分 available、configured/enabled、supported-in-mode、applied 和 observed status。保存、生成和运行状态分开；未观测到运行状态返回 unknown/unavailable，不回退成 enabled 即 running。

本次完整支持 AdBlock。其他已有模块可登记为 generation-only、unsupported 或 system-managed，按实际能力返回；不得因存在页面或旧配置就声称可运行。未注册 ID 的历史配置保留供导出迁移，但不可启用或应用；启用时返回 plugins.<id> 对应的字段错误。禁用的旧配置不应阻断基础路由。

新写入统一校验 plugin ID、开关、已知模块配置字段及依赖。保留 JSON 大整数和既有秘密引用语义；通过主配置、插件端点和恢复入口写入时约束一致。敏感值不得出现在日志、状态或字段错误中。

## 首个模块：AdBlock

- 复用 plugins.adblock.enable 和 config.entries，提供多行域名输入和明确启用开关。
- 仅支持显式域名规则。校验域名、拒绝换行和 dnsmasq 指令注入，规范化、去重并限制总数量及长度；精确上限由实现确定并测试边界。
- 明确域名规则包含其子域。dnsmasq 使用同时覆盖 A/AAAA 的阻断配置；必须在 VM 中验证，不能只检查生成文本。
- lists 订阅下载、刷新定时器、统计和外部 AdGuard Home 不在本次范围。历史 lists 保留供迁移/导出；启用带非空 lists 的配置明确报不支持，不静默忽略。页面展示这一边界。
- AdBlock 依赖路由器托管的本地 DNS；启用时若 DNS 关闭则在修改网络前拒绝，并定位字段。不得修改系统其他 dnsmasq 实例。
- managed 模式将规则纳入受管理的 dnsmasq 代际配置，经过校验后与核心同一次 apply 激活；不引入额外 root 守护进程，也不从低权限 API 控制 systemd。
- 停用时移除本模块规则，客户端恢复上游解析，不残留旧 generation 规则。仅生成模式只产出文件，状态明确未应用运行期。
- 应用错误必须影响任务最终结果，不再把模块失败作为成功提示；使用现有 last-good 恢复机制，不增加 LAN 改址倒计时回滚。
- 网络核心恢复与模块恢复使用同一份确认配置。API 重启、executor 重启和整机重启后状态仍可解释，不能将草稿误当运行配置。

## 页面及系统集成

保持原生 JavaScript 框架与双份静态资源同步。插件管理页展示支持模式、依赖、配置和实际应用状态；不支持模块不显示可成功启用的假开关。导航来自实际注册信息，核心 IPv6 不因旧 plugins.ipv6 开关被禁用。

NixOS 通用模块提供插件允许清单/支持集，API 与 executor 使用同一声明；默认选择须保留既有基础路由行为。AdBlock 不新增外部依赖下载。系统托管的 ZeroTier/Tailscale 等不因同名草稿而被启动或停止。插件钩子不得调用旧通用服务重载逻辑误接管系统服务。

不修改原始 nixos-home 工作区，不部署实体 gw，不运行主机网络变更。新的验证结果必须绑定修改后的版本；f7905d02 的旧通过记录仅作基线。

## 验收

1. Go：注册冲突、字段/依赖校验、ID 边界、秘密与并发语义、未知历史配置、启停生成、失败传播及旧 SSH 配置/备份/last-good 迁移。
2. 权限：API 不执行模块特权动作；executor 拒绝未授权能力或不支持模式；不存在任意命令入口。
3. 浏览器：SSH 入口移除、旧链接说明、插件能力展示、AdBlock 编辑保存应用、冲突保留输入、错误反馈；双份资源一致。
4. Nix 模块：系统 SSH 关闭、多监听端口、插件声明一致性及系统托管服务不被接管。
5. VM：真实上游 DNS 对测试域名返回已知 A/AAAA；客户端应用前可解析，启用后域名和子域均阻断，普通域名正常，停用后恢复。通过真实 HTTP API 配置并等待任务结果。
6. VM：非法规则不改变现网；执行器重启与整机重启保持已应用规则；启用状态下关闭本地 DNS被拒绝；规则切换后旧规则不残留；SSH 服务与监听保持系统配置，既有管理边界仍生效。
7. 根据实际影响运行 Go/race/vet、浏览器、模块及相关路由/权限/IPv6 VM 回归。未重新执行的旧检查明确列出，不沿用旧候选的全通过结论。
