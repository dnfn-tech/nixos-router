# gw 硬件验收执行前确认单

本文件是待用户审核的后续方案，不代表已批准操作实体 gw。本轮开发只运行隔离 VM/容器，不连接、部署或修改 gw。

## 候选范围

IPv4 基本网关：WAN DHCP/静态、单 LAN 网桥、DHCP/DNS、NAT/端口转发、按 MAC 阻断路由流量、LAN 管理面、单 WPA2 AP、应用失败恢复、last-good 启动恢复。高级能力未实现时由后端拒绝，界面声明范围。5 GHz 仅支持非 DFS 信道；实际国家法规、驱动能力仍由 hostapd 检查。

## 审核输入

用户先审核 `gw-readiness.md` 的实际通过证据、源码改动、制品标识与本方案，再决定是否授权实体测试。软件模拟不能证明 MT7927 固件、实际端口映射、WAN 接入要求、射频表现或真实负载。

本机保存的 gw 配置快照使用：WAN enp3s0；br0 的有线成员 enp4s0/enp5s0/enp6s0；有线网段192.168.124.0/24；WiFi wlp1s0 当前为独立192.168.125.0/24；Kea DHCP4。此处不是实体机器现状确认。

候选采用单 LAN：若选择把 WiFi 桥接到 br0，无线客户端将迁入192.168.124.0/24，旧192.168.125.0/24与相应静态地址/ACL/端口转发须逐项审查；不能原样保留旧双网段行为。Kea 租约不会自动导入 dnsmasq，静态租约需要显式迁移并排查重复地址。

## 获得实体测试授权后才执行

1. 先只读核实 gw 的硬件、系统版本、接口MAC/端口、网络管理服务、WAN接入模式、无线驱动/固件/法规及现有路由/DHCP/NAT规则；核对本地配置快照是否过期。
2. 准备串口/本地显示键盘等独立控制通道；确认人工恢复可用。记录当前 NixOS system generation、配置备份、管理地址和认证方式。不要把已有SSH连接当作唯一恢复入口。
3. 选用明确的维护窗口和独立测试客户端。确定新接口allowlist、LAN地址池、DNS、静态租约、管理端口。桥不列入wired allowlist；WiFi单独配置。真实密码通过运行时0600文件提供，不写入Nix store或代码仓库。
4. 构建并核对候选制品版本。先评估模块断言，再在明确批准的切换步骤中停止旧网络所有者：NetworkManager/networkd/dhcpcd/ConnMan，以及原Kea/dnsmasq/hostapd和NixOS防火墙/NAT/nftables。不能让两套管理器共同控制相同资源。
5. 从LAN有线客户端验证登录、真实状态与租约、DNS、互联网连通性，再逐项验证保存与应用、WAN续租/断线恢复、静态WAN、NAT、端口转发增删、MAC阻断、管理口WAN隔离。IPv6虽不提供路由功能，也要检查管理口不可从WAN IPv6绕过限制。
6. 无线验证实际关联/WPA2/DHCP、密码错误、关闭/重开、重启恢复，再测MT7927稳定性、覆盖/吞吐、并发客户端和长时间运行。软件hwsim结果只能作为协议集成证据。
7. 检查失败应用恢复、草稿不自动生效、进程重启/整机重启及掉电恢复；归档日志、配置摘要与每项结果。未通过项修复后复验，不能用界面成功提示代替客户端实际结果。

## 人工恢复原则

不增加 LAN 地址变更后的自动超时回滚。用户更改 LAN 地址后应使用新地址重新连接；如果失联，通过独立控制通道处理。

普通应用失败由引擎恢复 last-good；恢复本身失败必须显示失败，不能伪报已恢复。损坏草稿保留原文件，启动使用有效last-good并提示修复。损坏last-good或未知桥归属时停止接管，不冒险清空外部网络。

首次创建网桥到打标之间若恰好强杀，可能留下无归属标签桥。必须先通过独立控制台核实该桥是否为失败候选所建，再人工清理或恢复旧系统；禁止为了启动直接把任意已有桥认作自有桥。

恢复旧系统时先停止候选专属服务，按已记录的旧 NixOS generation/配置恢复旧网络所有者，并从客户端验证 DHCP/DNS/路由。具体命令需以现场实际系统路径和已审核恢复记录为准，本文件不提供盲执行脚本。
